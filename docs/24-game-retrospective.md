# 24개 일일 게임 리뷰 회고

작성일: 2026-05-06

## 리뷰 목적

24개 일일 게임을 개별 완성도와 시리즈/제작 파이프라인 품질 양쪽에서 점검한다. 이 문서는 즉시 수정할 문제와 다음 일일 게임 생성 품질을 높이는 개선 항목을 분리하기 위한 기준 문서다.

현재 정적 검증 결과:

- `node tools/verify-repo.js`: 통과
- `node tools/verify-skills.js`: 통과
- 모든 `games/*/script.js`의 `node --check`: 통과
- 모든 게임은 `index.html`, `style.css`, `script.js`, `meta.json` 4파일 구조를 유지한다.

## 리뷰 축

1. 게임성/재미: 10초 안에 핵심 루프가 이해되는지, 피드백이 즉각적인지, 반복 플레이 이유가 있는지, 난이도 상승이 체감되는지 본다.
2. 조작/모바일 UX: 첫 입력, 터치/드래그/홀드/스와이프 안정성, 키보드 fallback, 실패 원인 전달을 본다.
3. 콘셉트 다양성: 인접 날짜의 장르/조작/플레이 감각 반복, 부족한 계열, 이름만 다른 유사 게임 여부를 본다.
4. 난이도/라운드 설계: 클리어 시 다음 라운드, 실패 시 라운드 1 복귀, 라운드별 증가값, 초반/후반 압박을 본다.
5. 시각/정보 설계: `design-guidelines.md` 준수, HUD/안내/오버레이 가독성, 게임별 시각 차별성을 본다.
6. 기술 품질/유지보수성: 런타임 오류 가능성, pointer/resize/timer/animation loop 처리, 코드 복잡도와 반복을 본다.
7. 카탈로그/메타데이터 품질: 제목/장르/controls/tagline 정확성, 카드 탐색성, 향후 필터 필요성을 본다.
8. 생성 파이프라인 개선: `tools/plan-game.js` 반복 제안, 유사도 자동 체크, smoke test와 검증 강화 가능성을 본다.

## 전체 회고

### 잘 된 점

- 24개 게임의 장르명은 모두 다르며, 하루 단위 산출물의 형식 일관성은 안정적이다.
- 2026-04-20 이후 게임들은 대체로 라운드 클리어/실패 루프 규칙이 코드와 메타데이터에 일관되게 반영되어 있다.
- 2026-04-24부터 퍼즐, 리코셰, 기억, 밸런스, 다이얼 등 플레이 감각이 넓어지면서 초기보다 실험 폭이 커졌다.
- 외부 에셋 없이 캔버스/DOM/CSS만으로 시각 요소를 만들었고, 정적 호스팅 제약을 유지했다.

### 반복 패턴

- 조작 계열 분포는 `tap` 9개, `drag` 6개, `hold` 4개, `swipe` 4개, `direction` 1개로 탭/드래그에 치우친다.
- `좌우 스와이프`, `좌우 드래그`, `홀드 릴리즈`는 각각 2회씩 반복된다.
- 자동 기획기 `tools/plan-game.js`의 장르 풀이 5개뿐이라 최근에도 `Timing Stack` 제안이 반복됐다.
- 2026-05-01 이후 게임 화면 shell과 CSS 구조가 매우 유사해져 제작 안정성은 높지만 시리즈 감각은 다소 평평해졌다.

### 부족한 계열

- 리듬/박자 기반 입력
- 선택형 미니 전략 또는 덱/카드형 판단
- 공간 추론을 더 쓰는 퍼즐
- 물리 반응을 명확하게 체감하는 게임
- 비동기 위험 예측이나 우선순위 판단 게임

## 개선 백로그

### P0

- 없음. 현재 정적 검증과 JS 문법 검사는 통과한다.

### P1

- 2026-04-13부터 2026-04-16까지 초기 4개 게임을 현재 라운드 규칙에 맞게 리마스터한다.
- 2026-04-24 `크로노 드리프트`는 복잡도와 런타임 리스크가 가장 높으므로 브라우저 smoke test 우선 대상으로 삼는다.
- `tools/plan-game.js`의 장르/조작/목표 풀을 확장하고 최근 메타데이터 기반 중복 회피를 자동화한다.

### P2

- 모든 게임에 `controlFamily`, `difficulty`, `playStyle` 같은 선택 메타 확장을 검토한다.
- 반복되는 게임 shell CSS와 HUD 구조를 템플릿 문서 또는 생성 가이드로 정리한다.
- 색상 의존 게임은 보조 문양/텍스트를 강화해 접근성을 높인다.
- 카탈로그에 조작 계열/세션 길이/플레이 스타일 필터를 추가할지 검토한다.

### P3

- `tools/review-games.js` 결과를 CI 또는 정기 회고 루틴에 연결한다.
- Playwright 같은 브라우저 smoke test는 정적 검증으로 잡히지 않는 입력/캔버스 문제를 발견할 필요가 생길 때 추가한다.
- 월간 회고 문서 템플릿을 만들어 “잘 된 계열/부족한 계열/다음 7일 금지 패턴”을 남긴다.

## 다음 7일 생성 가이드

- 금지 또는 억제: 타이밍 스택, 좌우 분류, 드래그 밸런스, 홀드 밴드 유지.
- 우선 시도: 리듬 입력, 선택형 미니 전략, 공간 추론 퍼즐, 비동기 우선순위 판단, 제한된 리소스 관리.

- 자동 제안이 최근 10일 안의 genre/control family와 겹치면 폐기하고 다른 풀에서 다시 선택한다.

## 반복 실행

메타데이터와 휴리스틱 요약은 다음 명령으로 재생성한다.

```sh
node tools/review-games.js
```

정적 품질 확인은 다음 명령으로 수행한다.

```sh
for f in games/*/script.js; do node --check "$f" || exit 1; done
node tools/verify-repo.js
node tools/verify-skills.js
```
